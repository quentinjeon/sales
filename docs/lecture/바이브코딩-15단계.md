# 바이브코딩 15단계 — 이 시스템을 처음부터 만드는 순서

> [바이브코딩-5단계-제작흐름.md](바이브코딩-5단계-제작흐름.md) 의 5단계를 **실제 작업 단위 15개**로 쪼갠 것입니다.
> 각 단계마다 **붙여넣을 프롬프트**와 **확인할 숫자**가 있습니다.
>
> 각 단계의 「왜 필요한가」는 **이 시스템을 실제로 만들면서 터진 버그**입니다.
> 지어낸 예시가 아니라, 그 단계를 건너뛰었을 때 실제로 일어난 일입니다.

```
정의(1~3)  →  데이터(4~6)  →  명세(7~8)  →  개발(9~13)  →  굳히기(14~15)
```

---

## 원칙 세 줄

1. **한 단계에 하나만 시킨다.** "다 만들어줘"는 실패합니다.
2. **매 단계 숫자로 확인한다.** 안 맞으면 다음으로 안 갑니다.
3. **틀린 걸 조용히 넘기지 않는다.** 이 시스템의 버그는 전부 "조용히 틀림"이었습니다.

# 정의 (1~3단계)

코드를 한 줄도 안 쓰는 구간입니다. **여기서 30분 쓰면 나중에 3일을 법니다.**

## 1단계 — 한 문장 정의 + 안 만들 것

### 무엇을

시스템을 한 문장으로 쓰고, **만들지 않을 것**을 그보다 길게 씁니다.

```
만든다:  엑셀 3장을 넣으면 그 달의 제품별·채널별 이익을 보여주는 웹 도구

안 만든다:
  로그인·권한      → 혼자 쓰는 내부 도구. 127.0.0.1 바인딩으로 대체
  채널 API 연동    → 채널마다 인증·쿼터가 달라 유지비가 큼. 엑셀로 충분
  재고·발주        → 손익 계산에 재고 흐름이 필요 없음
  부가세 정밀 계산  → 세무는 별도 영역. 전부 부가세 제외로 통일
  반품·쿠폰 정밀   → 나중에(P1)
```

### 왜 필요한가

AI는 **범위를 안 주면 상상합니다.** "매출 관리 시스템"이라고만 하면 로그인 화면부터 만듭니다.
안 만들 것을 **이유와 함께** 적으면 AI가 그 경계를 지킵니다.

### 프롬프트

```
나는 이런 도구를 만들려고 해. 아직 코드는 짜지 마.

[한 문장 정의]
[안 만들 것 5가지와 각각의 이유]

이 범위에서 빠진 게 있는지, 혹은 범위 안인데 내가 안 적은 게 있는지 물어봐.
```

### ✅ 확인

- 안 만들 것이 5개 이상이고, 각각 **이유**가 붙어 있다
- AI가 "이건 범위에 넣어야 하지 않나요?"라고 되물었고, 그에 답했다

---

## 2단계 — 핵심 개념 하나를 고정한다

### 무엇을

이 시스템의 **계산 단위**를 정의합니다. 이 시스템에서는 **딜**입니다.

```
딜 = 채널 × 제품 구성 × 가격 티어 × 기간
```

그리고 그게 왜 제품 단위가 아닌지를 **숫자로** 보입니다.

| | 한빛홈쇼핑 (9.5%) | 몰이십일 (13.0%) |
|---|---:|---:|
| 판매가 | 24,900 | 24,900 |
| − 수수료 | 2,366 | 3,237 |
| − 원가 (760 × 24개입) | 18,240 | 18,240 |
| − 물류비 | 3,000 | 3,000 |
| **= 기여이익** | **1,294 (5.20%)** | **423 (1.70%)** |

같은 제품, 같은 가격인데 **이익 67% 차이.**

### 왜 필요한가

이 개념이 흔들리면 **테이블 설계가 통째로 틀립니다.** "제품별 이익" 컬럼을 만들고 나면
나중에 채널별로 쪼갤 수 없습니다. 개념을 먼저 못 박아야 스키마가 따라옵니다.

### 프롬프트

```
이 시스템의 계산 단위는 '딜'이야. 딜 = 채널 × 제품 구성 × 가격 티어 × 기간.

[위 비교표]

이 개념으로 봤을 때 필요한 테이블이 뭔지 나열해줘. 아직 코드는 짜지 마.
그리고 이 개념 때문에 생기는 함정이 뭔지도 알려줘.
```

### ✅ 확인

- AI가 `제품(SKU)`과 `딜`을 분리했다
- **딜 구성(component)** 을 별도 테이블로 제안했다 — 세트·증정품 때문
- 왜 `제품 = 딜`이면 안 되는지 스스로 설명할 수 있다

## 3단계 — 계산 규칙을 손으로 검산한다

### 무엇을

계산식을 쓰고, **주문 한 줄을 손으로 계산**해 봅니다.

```
순매출   = 판매금액                          (취소면 0)
수수료   = 실적값 우선, 없으면 순매출 × 채널 요율
원가     = Σ(구성 SKU 수량 × 판매일 기준 매입가) × 판매수량
물류비   = 채널 배송비 모델 × 판매수량
기여이익 = 순매출 − 수수료 − 자사부담할인 − 원가 − 물류비
마진율   = 기여이익 ÷ 순매출
```

```
즉석밥 24개입 · 특가 24,900원 · 한빛홈쇼핑(9.5%) · 1건

① 24,900
② 24,900 × 9.5% = 2,365.5 → 2,366
③ 760 × 24 × 1 = 18,240
④ 3,000
⑤ 24,900 − 2,366 − 18,240 − 3,000 = 1,294
⑥ 1,294 ÷ 24,900 = 5.20%
```

### 왜 필요한가 — 실제로 터진 것

이 검산이 나중에 **정답지**가 됩니다. 그리고 여기서 정하지 않으면 아래가 전부 애매해집니다.

| 엣지케이스 | 안 정하면 | 정답 |
|---|---|---|
| 취소 건 | 원가만 남아 취소 1건마다 원가 전액 손실 | 매출·수수료·원가·물류비 **전부 0** |
| 증정품 | 원가에서 빠져 이익이 부풀려짐 | **포함** |
| 매입가 시점 | 8월에 매입가 올리면 7월 손익이 소급 변경 | **판매일 기준** |
| 반올림 | 여러 번 반올림해 합계가 어긋남 | **수수료에서 한 번만** |

### 프롬프트

```
계산 규칙이야. [위 6줄]

아래 엣지케이스에서 각각 어떻게 처리해야 하는지 나에게 물어봐. 내가 답할게.
- 취소된 주문
- 증정품이 포함된 구성
- 매입가가 중간에 바뀐 경우
- 반올림을 어디서 할지
- 순매출이 0인 경우 마진율
```

### ✅ 확인

- 위 예시를 손으로 계산해서 **1,294원 / 5.20%** 가 나온다
- 엣지케이스 5개의 답이 문서에 적혀 있다

# 데이터 (4~6단계)

## 4단계 — 인풋 3장의 컬럼을 정의한다

### 무엇을

| 파일 | 성격 | 갱신 |
|---|---|---|
| `01_상품정보.xlsx` | 마스터 | 제품 늘 때만 |
| `02_채널정보.xlsx` | 마스터 | 수수료 바뀔 때만 |
| `03_매출_YYYY-MM.xlsx` | 원장 | **매달** |

각 파일의 컬럼과 **필수/선택**을 정합니다. 특히 매출 파일은 **채널마다 컬럼명이 다릅니다.**

| 논리 필드 | 한빛홈쇼핑 | 스위프트 | 몰이십일 | 굿마켓 |
|---|---|---|---|---|
| 주문일 | 주문일자 | 결제일 | 구매확정일 | 주문일 |
| 상품명 | 상품명 | 노출상품명 | 상품명 | 주문상품 |
| 판매금액 | 판매금액 | 결제금액 | 상품금액 | 정산금액 |
| 수수료 | 수수료 | **없음** | 서비스이용료 | **없음** |

### 왜 필요한가

컬럼명을 코드에 직접 박으면 채널이 어드민을 개편할 때마다 코드를 고쳐야 합니다.
**논리 필드 → 키워드 목록** 구조로 가야 키워드만 추가하면 됩니다.

그리고 **마스터와 원장의 구분**이 여기서 결정됩니다. 이걸 안 나누면 나중에 업로드 화면이
"매달 상품정보도 다시 올려야 하나?"로 헷갈립니다.

### 프롬프트

```
인풋은 엑셀 3장이야.
[각 파일의 컬럼표와 필수 여부]

매출 파일은 채널마다 컬럼명이 달라. [비교표]

컬럼명을 코드에 박지 않고 읽는 방법을 제안해줘. 아직 구현은 하지 마.
그리고 필수 컬럼을 못 찾으면 어떻게 해야 할지도 말해줘.
```

### ✅ 확인

- "논리 필드 → 후보 키워드 목록" 방식이 나왔다
- **필수 컬럼이 없으면 예외를 던진다**로 정해졌다 (빈 값으로 채우면 매출이 증발)

## 5단계 — 목업 데이터를 설계한다

### 무엇을

실제 데이터가 아니라 **교보재가 되도록 설계된** 가상 데이터를 만듭니다.

이 시스템의 목업은 이렇게 설계했습니다.

| 설계 의도 | 구현 |
|---|---|
| 구성수량 함정을 극적으로 | 24개입 · 30롤 · 100캡슐 · **1000개입** |
| 카테고리별 마진 구조 차이 | 생필품 0~20% vs 건강기능식품 24~45% |
| 특가 적자를 만들기 | 23종 중 5종이 특가에서 마이너스 |
| 채널 수수료 격차 | 6.8% ~ 24.0% (3.5배) |
| 매핑 실습거리 | 일부러 안 맞는 상품명 7건 |

### 왜 필요한가 — 실제로 겪은 것

처음엔 구성수량이 2~4인 데이터로 만들었습니다. 그랬더니 구성수량을 빼먹어도
"좀 이상한데?" 수준이라 **함정이 안 보였습니다.**

1000개입으로 바꾸니 이렇게 됐습니다.

```
원가 = 14원 × 1,000개 = 14,000원
구성수량을 빼먹으면 = 14원      ← 1000배 차이
```

**목업 데이터는 아무 숫자나 넣으면 안 됩니다. 배울 게 드러나도록 설계해야 합니다.**

### 프롬프트

```
목업 데이터를 만들 거야. 조건:
- 제품 23종. 구성수량이 2부터 1000까지 다양하게
- 특가에서 적자인 제품이 5종 나오도록 원가·가격 설계
- 카테고리별로 마진 구조가 다르게 (생필품 얇게, 건강기능식품 두껍게)
- 채널 수수료는 6.8%~24% 범위

먼저 제품표만 만들고, 계획 마진율을 계산해서 위 조건이 맞는지 보여줘.
```

### ✅ 확인

- 특가 적자가 **정확히 의도한 수만큼** 나온다
- 마진율 범위가 넓다 (예: −9.86% ~ 44.86%)
- 실존 기업·브랜드명이 **하나도** 없다

## 6단계 — 정답지를 만든다 ★

### 무엇을

목업 데이터를 넣었을 때 나와야 하는 **최종 숫자**를 확정합니다.

```
주문 건수    3,707
총매출      77,667,300
채널 수수료   8,711,768
원가        52,072,450
물류비      10,928,600
기여이익      5,954,482
마진율           7.67%
미매핑       7건 / 214,300원
적자 딜          3건
```

### 왜 필요한가

**이게 없으면 "다 만들었다"를 판단할 수 없습니다.**
화면이 뜨는 것과 숫자가 맞는 것은 완전히 다른 문제입니다.

그리고 이 숫자가 나중에 **회귀 테스트**가 됩니다. 계산식을 건드렸을 때
여기가 깨지면 뭔가 잘못한 겁니다.

> 파일 합계는 77,881,600원인데 정답은 77,667,300원입니다.
> 차이 214,300원이 미매핑입니다. **이 차이를 설명할 수 있어야** 제대로 만든 겁니다.

### ✅ 확인

- 전체 합계 + 채널별 + 적자 딜까지 숫자가 고정됐다
- 파일 합계와 집계 매출의 차이를 설명할 수 있다

# 명세 (7~8단계)

## 7단계 — PRD를 쓴다 ★ 가장 중요

### 무엇을

지금까지 정한 걸 **AI에게 통째로 줄 수 있는 문서** 하나로 합칩니다.

| 절 | 내용 |
|:-:|---|
| 1~3 | 한 줄 요약 · 왜 만드나 · **범위와 비범위** |
| 4 | 입력 파일 3종 컬럼 명세 |
| 5 | **계산 규칙 + 손 검산 예시** |
| 6 | 상품명 매칭 규칙 |
| 7~8 | 화면 · 결과 엑셀 |
| 9 | **검수 기준 (6단계의 숫자)** |
| 10~11 | 기술 스택 · 구현 순서 |
| 12 | 자주 나오는 실수 |

### 왜 필요한가

대화가 길어지면 AI는 앞을 잊습니다. PRD가 있으면 **"PRD 5절 보고 다시 해줘"** 한 마디로 되돌릴 수 있습니다.

### 프롬프트

```
아래는 내가 만들 시스템의 명세서(PRD)야. 전부 읽고, 질문이 있으면 먼저 물어봐.
아직 코드는 짜지 마.

[PRD 전문]
```

**"아직 코드는 짜지 마"** 가 핵심입니다. 이해했는지 먼저 확인합니다.

### ✅ 확인

- AI가 **질문을 3개 이상** 했다 (질문이 없으면 명세가 모호한 게 아니라 AI가 안 읽은 것)
- 9절의 검수 기준 숫자가 들어 있다

---

## 8단계 — mock HTML로 화면을 먼저 본다

### 무엇을

코드를 짜기 전에 **정적 HTML로 화면을 그려서 눈으로 확인**합니다.

```
mock/
├── index.html          화면 목록 + 데이터 흐름
├── 01-상품DB.html
├── 02-채널DB.html
├── 03-매출데이터.html
├── 04-대시보드.html
└── 05-리포트.html
```

### 왜 필요한가

화면을 안 보고 만들면 **다 만든 뒤에 "이게 아닌데"** 가 나옵니다.
HTML 목업은 30분이면 만들고, 고치는 것도 30분입니다. 코드는 3일입니다.

그리고 목업을 만들다 보면 **PRD에 빠진 게 드러납니다.**
"이 표에 이 컬럼이 있어야 하는데 명세에 없네" → PRD로 역류시킵니다.

### 프롬프트

```
PRD 7절의 화면을 정적 HTML로 그려줘. 실제 동작은 필요 없고 보기만 되면 돼.
숫자는 PRD 9절의 검수 기준 값을 그대로 써줘.
다크모드도 되게 해줘.
```

### ✅ 확인

- 브라우저로 열어서 **"내가 원한 게 이거다"** 라고 말할 수 있다
- 목업을 보다가 PRD를 고친 게 1개 이상 있다

# 개발 (9~13단계)

**한 단계마다 숫자를 확인하고, 안 맞으면 다음으로 가지 않습니다.**

## 9단계 — 데이터 모델 + 계산 엔진 (테스트 먼저)

### 무엇을

테이블을 만들고 계산 함수를 만듭니다. **테스트를 같이 만듭니다.**

### 왜 필요한가 — 실제로 터진 것

계산 엔진은 이 시스템의 심장이고, **틀려도 화면은 멀쩡하게 뜹니다.**
이번 프로젝트에서 실제로 나온 계산 버그 4개:

| 버그 | 증상 |
|---|---|
| 취소 건에 원가·물류비가 남음 | 취소 1건마다 원가 전액이 이익에서 사라짐 |
| 요율 근거를 읽고 버림 | 실측 요율(9.5%)인 채널에 `추정` 배지가 붙음 |
| 매입가를 시점 없이 조회 | 이력 행이 생기는 순간 과거 손익이 바뀜 |
| 주별 화면이 가짜 날짜 생성 | `"2026-W3-15"` — 예외 없이 통과하면서 엉뚱한 값 |

**넷 다 화면은 200으로 잘 떴습니다.** 테스트가 없으면 못 잡습니다.

### 프롬프트

```
PRD 5절의 계산 규칙을 구현해줘. 순수 함수로, DB 쓰기는 하지 말고.

같이 테스트도 만들어줘:
- PRD 5절 예시 한 줄 → 기여이익 1,294원
- 취소 건 → 매출·수수료·원가·물류비가 전부 0
- 증정품이 원가에 포함되는지
- 매입가 이력을 추가해도 과거 기간 원가가 안 변하는지
- 순매출 0일 때 마진율이 null인지
```

### ✅ 확인

```bash
pytest -q     # 전부 통과
```
- PRD 5절 예시가 **1,294원**
- 23제품 × 3티어 계획 마진율이 정답지와 일치

## 10단계 — 엑셀 적재 (왕복 검증)

### 무엇을

엑셀 3장을 읽어 DB에 넣습니다.

### 왜 필요한가 — 검증 방법이 핵심

적재가 맞는지 확인하는 가장 강력한 방법은 **왕복(round-trip)** 입니다.

```
DB → 엑셀로 내보내기 → 빈 DB에 다시 넣기 → 숫자가 같은가?
```

이번에 실제로 돌린 결과:

```
항목       원본 DB      엑셀 재적재    일치
총매출     77,667,300   77,667,300    ✓
기여이익    5,954,482    5,954,482    ✓
미매핑        214,300      214,300    ✓
```

이게 맞으면 **읽기·쓰기·계산이 전부 맞다**는 뜻입니다.

### 프롬프트

```
PRD 4절대로 엑셀 3장을 읽어서 DB에 넣어줘.
채널별 시트의 컬럼명이 다르니 키워드 표로 찾고, 필수 컬럼이 없으면 예외를 던져줘.

만들고 나서 빈 DB에 3장을 넣고 총매출·기여이익·미매핑을 출력해줘.
정답은 77,667,300 / 5,954,482 / 7건 214,300원이야.
```

### ✅ 확인

- 빈 DB에 엑셀 3장만 넣어서 **정답지와 완전히 일치**
- 필수 컬럼을 지운 파일을 넣으면 **예외가 난다**

## 11단계 — 매핑 엔진

### 무엇을

채널 상품명을 제품 DB의 딜에 연결합니다.

```
① 등록된 규칙 조회
② 정규화 후 정확일치 → 규칙으로 자동 등록
③ 실패 → 미매핑 큐 (버리지 않음)
```

### 왜 필요한가 — 실제로 터진 것

**미매핑을 버리면 매출이 조용히 증발합니다.**

그리고 여기서 가장 위험한 실수는 **구성이 다른 딜에 붙이는 것**입니다.
이번에 실제로 일어난 일:

```
채널 상품명   온담 홈캉스 세트 (즉석밥 12개 + 즉석국 8개 + 김자반 2봉)
잘못 붙인 딜  온담 종이컵 1000개입

잡힌 원가     14,000원   ← 종이컵 원가
실제 원가     20,660원
이익          21,381원 (49.84%)   ← 실제로는 14,721원 (34.31%)
```

**원가 6,660원이 통째로 이익으로 둔갑했습니다.**

그래서 화면에 세 가지가 필요합니다.

| 기능 | 이유 |
|---|---|
| 미매핑 큐 상시 노출 | 버리지 않는다는 약속 |
| **여러 제품을 조합해 새 딜 만들기** | 복합세트는 이것 말고 정답이 없음 |
| 가격 불일치 경고 | 잘못 붙은 걸 발견하는 신호 |

### 프롬프트

```
PRD 6절대로 상품명 매핑을 만들어줘.
정규화 후 정확일치만 자동 연결하고, 애매하면 미매핑으로 남겨줘.
틀리게 붙이느니 미매핑이 나아.

화면에는 미매핑 큐와 함께, 여러 SKU를 조합해 새 딜을 만드는 폼도 넣어줘.
복합세트는 기존 딜에 붙이면 원가가 틀리니까.
```

### ✅ 확인

- 미매핑이 **정확히 7건 / 214,300원**
- 복합세트를 조합해 매핑하면 원가가 **20,660원** (증정품 포함)
- 미매핑을 0건으로 만들면 파일 합계 = 집계 매출

## 12단계 — 집계 + 화면

### 무엇을

제품별·채널별·딜별로 집계하고 대시보드를 만듭니다.

### 왜 필요한가 — 실제로 터진 것

화면은 **틀려도 200으로 뜹니다.** 이번에 나온 화면 버그들:

| 버그 | 왜 안 보였나 |
|---|---|
| 드롭다운이 통째로 비어 있음 | 변수명 오타 → Jinja가 조용히 빈 값 렌더 |
| 빈 DB에서 3개 화면 500 | 데이터 있는 상태로만 테스트함 |
| 실적 수수료 채널의 요율이 `—` | NULL을 "모름"으로 표시 |

첫 번째를 막는 방법:

```python
templates.env.undefined = StrictUndefined    # 변수명 틀리면 즉시 실패
```

이걸 켜자마자 **다른 버그 하나가 더 잡혔습니다.**

### 프롬프트

```
PRD 8절대로 집계하고 대시보드를 만들어줘.
mock/04-대시보드.html 을 참고해줘.

템플릿 엔진은 StrictUndefined로 설정해줘 — 변수명을 틀리면 조용히 빈 값이
렌더되는 게 아니라 바로 에러가 나야 해.
```

### ✅ 확인

- 채널별 표가 정답지와 일치
- **적자 딜이 정확히 3건**
- 데이터가 **하나도 없는 상태**에서도 모든 화면이 뜬다

## 13단계 — 결과 엑셀 내보내기

### 무엇을

시트 6장짜리 결과 파일을 만듭니다.

```
01_요약  02_제품별  03_채널별  04_채널x제품  05_적자딜  06_미매핑
```

### 왜 필요한가

화면은 보는 것이고, 엑셀은 **넘기는 것**입니다. 회계·대표·거래처에 보낼 때 필요합니다.

`06_미매핑`은 **비어 있어도 항상 만듭니다.** 미매핑이 없다는 사실도 정보입니다.

### 프롬프트

```
결과를 엑셀로 내보내는 기능을 추가해줘. 시트 6장은 PRD 8절 표대로.
화면에서 쓰는 집계 함수를 그대로 재사용해줘 — 로직을 복제하면 화면과 엑셀 숫자가 갈라져.
```

### ✅ 확인

- 시트 6장, `05_적자딜` 3행, `06_미매핑` 3행
- 화면 숫자와 엑셀 숫자가 **완전히 같다**

# 굳히기 (14~15단계)

## 14단계 — 실패 경로를 만든다 ★ 대부분 건너뛰는 단계

### 무엇을

**정상 경로가 아니라 틀렸을 때**를 만듭니다.

| 실패 상황 | 처리 |
|---|---|
| 같은 파일을 두 번 올림 | 해시로 감지해 거부 |
| 다른 파일인데 주문번호가 겹침 | 겹치는 행만 건너뜀 |
| 다시 계산하고 싶음 | 교체 모드 (해당 채널×기간 삭제 후 재적재) |
| 잘못 매핑함 | 다시 매핑 (규칙까지 삭제) |
| 데이터가 하나도 없음 | 안내 문구 (500 금지) |
| 필수 컬럼이 없음 | 예외 + 어떤 컬럼인지 표시 |

### 왜 필요한가 — 실제로 터진 것

중복 검사가 없던 상태에서 **13초 간격으로 같은 파일을 두 번 올렸습니다.**

```
1회차   주문 3,707건 · 총매출  77,667,300원
2회차   주문 7,414건 · 총매출 155,334,600원   ← 정확히 2배
```

`sha256` 컬럼과 인덱스는 이미 있었는데 **빈 문자열만 넣고 있었습니다.**
설계는 되어 있는데 구현이 비어 있던 자리입니다.

### 프롬프트

```
실패 경로를 만들어줘. 하나씩:

1) 같은 매출 파일을 두 번 올리면 매출이 두 배가 돼. 파일 해시로 막아줘.
2) 파일이 달라도 이미 적재된 주문번호는 건너뛰게 해줘.
3) 다시 계산하고 싶을 때를 위해 '기존 데이터 교체' 옵션을 넣어줘.
4) 데이터가 하나도 없는 상태에서 모든 화면이 500 없이 떠야 해.

각각 테스트도 같이 만들어줘.
```

### ✅ 확인

- 같은 파일 재업로드 → 차단되고 **합계가 안 변한다**
- 교체 모드로 올리면 **합계가 정확히 같다** (삭제 3,714 → 재적재 3,714)
- 빈 DB에서 전 화면 200

## 15단계 — 문서 · 캡처 · git

### 무엇을

| 산출물 | 내용 |
|---|---|
| `시스템-정의서.md` | 무엇을 보장하고 무엇을 보장하지 않는지 |
| `프로그램-소개.md` | 화면 캡처와 함께 보는 소개 |
| `README.md` | 실행 방법 · 검수 기준 |
| `docs/screenshots/` | 전 화면 캡처 |
| `.gitignore` | **실매출·DB·가상환경 제외** |

### 왜 필요한가

**한 달 뒤의 나는 남입니다.** 그리고 이 문서가 없으면 AI에게 다시 설명해야 합니다.

특히 **불변식 목록**을 남기세요. "이게 깨지면 손익이 틀린 것"의 목록입니다.

```
파일 합계 = 집계 매출 + 미매핑 금액          → test_i3b
같은 엑셀을 다시 넣어도 합계가 안 변한다      → test_i7
매입가 이력을 추가해도 과거 원가는 그대로     → test_c3
취소 건은 매출·원가·물류비가 전부 0          → test_c6e
```

### ⚠ .gitignore 부터

```gitignore
.venv/
data/              # DB — 언제든 다시 만들 수 있음
*.db
docs/upload/       # ★ 실매출 원자료 — 절대 올리지 마세요
.env
```

### 프롬프트

```
.gitignore 부터 만들어줘. 실매출 엑셀·DB·가상환경이 절대 안 올라가게.
그 다음 README와 시스템 정의서를 써줘.

정의서에는 '불변식' 절을 넣어줘 — 깨지면 손익이 틀리는 조건들과,
각각을 어느 테스트가 지키는지.
```

### ✅ 확인

```bash
git add -A && git status      # 실매출·DB·.venv 가 없다
pytest -q                      # 전부 통과
```

## 이 순서가 통하는 이유

```
1~3    무엇을 만들지 정한다        → AI가 상상하지 않는다
4~6    정답을 먼저 정한다          → "다 됐다"를 판단할 수 있다
7~8    명세와 화면을 먼저 본다      → 다 만든 뒤 갈아엎지 않는다
9~13   한 층씩 쌓고 매번 검증한다   → 어디서 틀렸는지 바로 안다
14~15  틀렸을 때를 만든다          → 조용히 틀리지 않는다
```

바이브코딩에서 실력은 **코드를 짜는 능력이 아니라 틀린 걸 알아채는 능력**입니다.
이 15단계는 전부 그걸 위한 장치입니다.
