# Part 1. 이 시스템은 무엇인가

## 1.1 한 줄 정의

> **엑셀 3장을 넣으면, 그 달에 무엇을 팔아 얼마가 남았는지를 제품별·채널별로 보여주는 웹 도구.**

```
📦 01_상품정보.xlsx   ─┐
🛒 02_채널정보.xlsx   ─┼─→  표준화 · 매핑 · 손익계산  ─→  📊 대시보드 + 📗 결과 엑셀
🧾 03_매출_YYYY-MM.xlsx ─┘
```

입력은 사람이 손으로 관리하는 엑셀이고, 출력은 **"이번 달 마진율 7.67%, 그리고 이 딜 3개는 팔수록 적자"** 같은 판단 가능한 문장입니다.

---

## 1.2 왜 필요한가 — 엑셀로는 안 되는 이유

온라인 셀러가 월말에 부딪히는 문제는 "매출을 모른다"가 아닙니다. 매출은 각 몰 어드민에 있습니다.
모르는 건 **남았는지**입니다.

| 엑셀에서 벌어지는 일 | 결과 |
|---|---|
| 몰마다 컬럼명·시트 구조가 다르다 | 합치는 데만 반나절 |
| 몰 상품명이 제각각이다 (`[특가]얼큰라면 5+1`) | 제품 DB와 연결이 안 됨 |
| 수수료를 "대충 13%"로 잡는다 | 실제는 6.8%~24.0% — **2배 이상 틀림** |
| 구성수량을 빼먹는다 | 원가 누락 → 이익이 부풀려짐 |
| 매칭 안 된 줄을 조용히 지운다 | **매출이 증발함** |

그래서 이 시스템의 목적은 "집계"가 아니라 **틀리지 않는 집계**입니다.
합계를 내는 건 쉽고, 틀린 줄 모르는 게 어렵습니다.

---

## 1.3 핵심 개념 — 딜(Deal)

이 시스템을 이해하는 데 필요한 개념은 사실상 하나뿐입니다.

> **딜 = 채널 × 제품 구성 × 가격 티어 × 기간**

같은 라면이라도

- A몰에서 5개입 12,900원에 팔 때
- B몰에서 5+1 증정 구성으로 14,900원에 팔 때
- 같은 A몰이라도 특가 기간에 9,900원에 팔 때

**이익이 전부 다릅니다.** 수수료율이 다르고, 원가(구성수량)가 다르고, 가격이 다르기 때문입니다.
그래서 손익은 "제품 단위"가 아니라 **딜 단위**로 계산해야 합니다.

제품별로만 보면 "라면은 이익 남는 제품"으로 보이지만, 딜별로 쪼개면 **그중 특가 딜 하나가 적자로 전체를 갉아먹고 있는 게** 보입니다. 이 시스템이 실제로 파는 가치가 그것입니다.

---

## 1.4 계산 규칙 (이게 시스템의 심장)

```
순매출   = 판매금액 (취소면 0)
수수료   = 실적값 우선, 없으면 순매출 × 채널 요율
원가     = Σ(딜 구성 SKU × 판매일 기준 매입가) × 판매수량
물류비   = 채널 배송비 모델 × 판매수량
기여이익 = 순매출 − 수수료 − 자사부담할인 − 원가 − 물류비
마진율   = 기여이익 ÷ 순매출
```

여기서 초보자가 반드시 틀리는 지점 세 곳:

1. **취소 건은 매출·수수료·원가·물류비가 전부 0.** 원가만 남기면 취소 1건마다 원가 전액이 이익에서 사라집니다.
2. **증정품도 원가에 포함.** 5+1의 6번째 개도 돈 주고 산 물건입니다.
3. **매입가는 판매일 기준.** 지난달 물건을 이번 달 매입가로 계산하면 과거 손익이 계속 바뀝니다.

---

## 1.5 시스템 경계

| 만든다 | 안 만든다 |
|---|---|
| 엑셀 3장 적재 · 컬럼 자동 인식 | 몰 API 연동 |
| 상품명 매핑 (정확일치 + 제안 + 수동) | 로그인 · 권한 관리 |
| 딜 단위 손익 계산 | 반품·쿠폰 정산 (P1) |
| 대시보드 · 제품별 · 채널별 화면 | 월말 정산 대사 (P1) |
| 결과 엑셀 6시트 내보내기 | 실시간 갱신 |

**혼자 쓰는 내부 도구**입니다. 사내 PC 한 대에서 돌리는 걸 전제로 합니다.

---

## 1.6 "다 만들었다"의 정의 — 검수 기준

만들었는지 여부는 느낌이 아니라 이 숫자로 판정합니다. 실습데이터 3장을 빈 DB에 넣었을 때:

| 항목 | 값 |
|---|---:|
| 총매출 | 77,667,300 |
| 채널 수수료 | 8,711,768 |
| 원가 | 52,072,450 |
| 물류비 | 10,928,600 |
| **기여이익** | **5,954,482** |
| 마진율 | 7.67% |
| 주문 | 3,707건 |
| 미매핑 | 7건 / 214,300원 |
| 적자 딜 | 3건 |

> **이 표가 이 프로젝트에서 가장 중요한 자산입니다.**
> 바이브코딩이 실패하는 가장 큰 이유는 "맞는지 확인할 방법이 없어서"입니다.
> 이 표가 있으면 AI가 아무리 그럴듯하게 말해도 **틀린 걸 즉시 압니다.**

# Part 2. 5단계 제작 흐름

## 전체 지도

| | 단계 | 산출물 | 주 도구 | 끝났다는 신호 |
|:-:|---|---|---|---|
| 1 | 인풋 파일 준비 | 엑셀 3장 | 엑셀 | 3장이 열리고, 컬럼이 무슨 뜻인지 말할 수 있다 |
| 2 | PRD 작성 | `docs/PRD.md` | **ChatGPT 왕복** | 모든 문장이 "맞았는지 확인 가능"하다 |
| 3 | 목업 확인 | `mock/*.html` | AI 코딩 도구 | 화면을 보고 "이거 아닌데"가 안 나온다 |
| 4 | 개발 · 서버 | 동작하는 앱 | AI 코딩 도구 | 검수 표 숫자가 전부 일치한다 |
| 5 | git 배포 | 저장소 · README | git | 남의 PC에서 clone 해서 돌아간다 |

**순서를 바꾸지 마세요.** 특히 2번을 건너뛰고 4번으로 가는 것이 실패의 90%입니다.
2번 없이 만든 코드는 "그럴듯하게 돌아가지만 숫자가 틀린 코드"가 됩니다.

각 단계는 **되돌아갈 수 있습니다.** 3단계에서 발견한 것은 2단계(PRD)에 반영하고 다시 내려옵니다.
아래 각 단계의 마지막에 "이전 단계로 역류시킬 것"을 적어 뒀습니다.

## 1단계 — 인풋 파일 3장 준비

### 왜 파일이 먼저인가

명세가 데이터를 정하는 게 아니라, **데이터가 명세를 정합니다.**
실제 파일을 열어 보지 않고 쓴 PRD는 반드시 현실과 어긋납니다. "채널마다 컬럼명이 다르다" 같은 사실은
파일을 열어야만 알 수 있고, 그게 이 시스템 난이도의 절반입니다.

### 준비할 3장

#### ① `01_상품정보.xlsx` — 무엇을 파는가

| 컬럼 | 예시 | 왜 필요한가 |
|---|---|---|
| 제품코드 | `P001` | 고유 식별자 |
| 제품명 | `얼큰라면 5개입` | 사람이 읽는 이름 |
| 구성 SKU | `SKU-RM-01` | 원가를 매기는 실제 물건 |
| **구성수량** | `5` | **빼먹으면 원가가 1/5 됨** |
| 매입가 | `780` | SKU 1개당 |
| 판매가(티어) | `12,900 / 11,900 / 9,900` | 정상가·행사가·특가 |

#### ② `02_채널정보.xlsx` — 어디서 파는가

| 컬럼 | 예시 | 왜 필요한가 |
|---|---|---|
| 채널코드 | `MALL21` | 매출 파일과 연결 |
| 채널명 | `몰이십일` | |
| **수수료율** | `13.5%` | **이익을 결정하는 최대 변수** |
| 요율 근거 | `계약서` / `추정` | 추정이면 화면에 `추정` 배지 |
| 배송비 모델 | `건당 2,800` | 물류비 계산 |
| 상태 | 운영 / 대기 | 대기 채널은 집계 제외 |

#### ③ `03_매출_YYYY-MM.xlsx` — 얼마나 팔았나

채널별로 시트가 나뉘어 있고, **시트마다 컬럼명이 다릅니다.** 이게 핵심 난관입니다.

| 채널 A | 채널 B | 채널 C | 실제 의미 |
|---|---|---|---|
| 주문번호 | 주문ID | 오더넘버 | 주문번호 |
| 상품명 | 판매상품명 | 옵션명 | 상품명 |
| 결제금액 | 실결제액 | 판매금액 | 순매출 |
| 수수료 | — | — | (2곳만 줍니다) |

### 직접 만들 때 지킬 것

- **한 파일 한 주제.** 상품/채널/매출을 한 파일에 섞지 않습니다.
- **헤더는 1행에.** 제목 행, 병합 셀, 소계 행 넣지 마세요. AI가 헤더를 못 찾습니다.
- **금액은 숫자로.** `12,900원` 같은 문자열이면 계산이 안 됩니다.
- **한 달치부터.** 처음부터 12개월 넣지 마세요. 틀렸을 때 어디가 틀렸는지 못 찾습니다.
- **개인정보는 지웁니다.** 수취인·주소·연락처는 손익 계산에 안 씁니다. 5단계(git)에서 사고 납니다.

수업에서는 만들어 둔 것을 씁니다 → `docs/lecture/실습데이터/`

### ✅ 1단계 완료 조건

- [ ] 3장이 엑셀에서 열린다
- [ ] 각 컬럼이 무슨 뜻인지 말로 설명할 수 있다
- [ ] 매출 파일의 채널코드가 채널정보 파일에 전부 존재한다
- [ ] 매출 파일 시트별 컬럼명 차이를 **메모해 뒀다** (2단계에서 씀)

## 2단계 — `docs/PRD.md` 작성 ★ 가장 중요

> PRD(Product Requirements Document) = **AI에게 주는 계약서.**
> 여기 안 적힌 건 AI가 지어냅니다. 여기 애매하게 적힌 건 AI가 자기 편한 대로 해석합니다.

**이 단계를 ChatGPT와 왕복하며 만듭니다.** 혼자 쓰면 빠뜨리고, AI 혼자 쓰게 하면 현실과 어긋납니다.
당신이 현실(1단계 파일)을 알고, ChatGPT가 문서 구조를 압니다. 그 둘을 붙이는 게 이 단계입니다.

### 2.1 PRD에 반드시 들어갈 13절

| 절 | 내용 | 없으면 생기는 일 |
|---|---|---|
| 1 | 한 줄 요약 | AI가 매번 다른 걸 만듦 |
| 2 | 왜 만드는가 | 판단이 필요할 때 기준이 없음 |
| 3 | 범위 — 만든다 / **안 만든다** | 로그인 · 권한 같은 걸 멋대로 만듦 |
| 4 | **입력 파일 명세** (컬럼·타입·예시) | 컬럼 이름을 지어냄 |
| 5 | **계산 규칙** (수식 + 손검산 예시) | 숫자가 틀림 |
| 6 | 상품명 매칭 규칙 | 미매핑을 조용히 버림 |
| 7 | 화면 목록 + 각 화면이 답하는 질문 | 예쁘지만 쓸모없는 화면 |
| 8 | 결과 엑셀 시트 구성 | |
| 9 | **검수 기준 (숫자 표)** | **완성 판정을 못 함** |
| 10 | 기술 스택 | 매번 다른 프레임워크로 갈아탐 |
| 11 | 구현 순서 | 화면부터 만들다 뒤엎음 |
| 12 | 자주 나오는 실수 | 같은 실수 반복 |
| 13 | 나중에 할 것 (P1) | 지금 필요 없는 걸 만듦 |

**4·5·9절이 전체의 70%입니다.** 나머지는 짧아도 됩니다.

### 2.2 ChatGPT 왕복 루프 — 5라운드

붙여넣어 쓰는 대본입니다. **한 번에 완성하려 하지 마세요.** 왕복이 목적입니다.

---

#### 라운드 0 — 역할 부여 + 재료 투입

```
너는 시니어 프로덕트 매니저야. 나는 온라인몰 셀러이고, 월별 매출·수익률 관리 도구를 만들려고 해.
지금부터 너와 함께 PRD를 완성할 거야.

규칙 3가지:
1. 내가 안 알려준 사실을 추측해서 채우지 마. 모르면 질문해.
2. 모든 요구사항은 "맞았는지 확인 가능한 문장"으로 써. ("빠르게" ❌ / "3초 이내" ✅)
3. 지금은 코드 쓰지 마. 문서만.

먼저 내가 가진 입력 파일 3장의 실제 컬럼을 붙여넣을게.
```

→ 이어서 **1단계에서 만든 파일의 컬럼명·샘플 2~3행을 그대로 복사해 붙여넣습니다.**
(엑셀에서 범위 선택 후 복사하면 ChatGPT에 표로 붙습니다. 스크린샷보다 텍스트가 낫습니다.)

---

#### 라운드 1 — 초안 요청

```
이 파일들로 만들 시스템의 PRD 초안을 써 줘. 목차는 이렇게:
1 한줄요약 / 2 왜 / 3 범위(만든다·안만든다) / 4 입력파일명세 / 5 계산규칙 /
6 상품명매칭 / 7 화면 / 8 결과엑셀 / 9 검수기준 / 10 기술스택 / 11 구현순서 /
12 흔한실수 / 13 나중에

지금은 4절과 5절만 자세히 써. 나머지는 제목만.
4절에는 컬럼마다 [이름 / 타입 / 필수여부 / 예시값 / 없을 때 동작]을 표로.
```

---

#### 라운드 2 — 계산 규칙 정밀화 ★ 여기가 승부처

```
5절 계산 규칙을 다시 쓰자. 다음을 반드시 명시해:

- 순매출 / 수수료 / 원가 / 물류비 / 기여이익 / 마진율 각각의 수식
- 취소 건은 어떻게 처리하나
- 수수료 실적값이 있는 채널과 없는 채널을 어떻게 다르게 처리하나
- 원가에 구성수량을 어떻게 반영하나
- 증정품(5+1의 6번째)의 원가는 누가 부담하나
- 매입가가 바뀌면 지난달 손익은 어떻게 되나

그리고 마지막에 **주문 1건을 손으로 검산하는 예시**를 넣어 줘.
숫자를 하나씩 대입해서 기여이익이 나오는 과정을 보여줘.
```

> 손검산 예시를 요구하는 이유: **수식이 틀렸으면 여기서 드러납니다.**
> 그리고 4단계에서 AI가 만든 코드를 이 예시 한 줄로 바로 검증할 수 있습니다.

---

#### 라운드 3 — 심문 (AI가 나에게 질문하게 만들기)

```
지금까지의 PRD를 개발자가 그대로 구현한다고 하자.
**해석이 갈릴 수 있는 지점 10개**를 찾아서, 나에게 질문 형태로 던져 줘.
각 질문마다 "네가 임의로 정하면 어떤 위험이 있는지"도 한 줄로.
```

전형적으로 이런 게 나옵니다 — 그리고 **여기서 나오는 답이 PRD의 진짜 내용**입니다.

- 매출 파일에 없는 채널코드가 나오면 에러? 무시? 미매핑?
- 같은 파일을 두 번 올리면?
- 판매수량이 0이거나 음수면?
- 한 주문에 상품이 2개면 행이 2개인가 1개인가?
- 월 경계에 걸친 주차는 어느 달로?

**질문에 답하고 → "그 답을 PRD에 반영해 줘"를 반복합니다.** 이 왕복이 PRD의 밀도를 만듭니다.

---

#### 라운드 4 — 검수 기준 확정

```
9절 검수 기준을 쓰자. 내가 실제 파일로 계산한 정답 숫자를 줄게. 이걸 표로 만들고,
"이 숫자가 안 맞으면 의심할 원인"을 각 항목마다 2~3개씩 달아 줘.

총매출 77,667,300 / 수수료 8,711,768 / 원가 52,072,450 / 물류비 10,928,600
기여이익 5,954,482 / 마진율 7.67% / 주문 3,707건 / 미매핑 7건 214,300원 / 적자딜 3건
```

정답 숫자가 아직 없다면? **엑셀에서 한 채널만 손으로 계산해서 부분 정답이라도 만드세요.**
정답 없이 4단계로 가면 완성 여부를 영원히 판정할 수 없습니다.

---

#### 라운드 5 — 자체 채점

```
완성된 PRD를 네가 처음 보는 개발자라고 생각하고 채점해 줘.
- 추측 없이 구현 가능한가? 불가능한 부분을 전부 지적해.
- "확인 불가능한 문장"을 전부 찾아서 확인 가능한 문장으로 고쳐 줘.
- 4절 컬럼 중 5절 계산에서 안 쓰이는 게 있으면 알려 줘 (불필요한 요구사항)
- 5절 계산에 필요한데 4절에 없는 데이터가 있으면 알려 줘 (구멍)
```

마지막 두 질문이 특히 유용합니다. **입력과 계산이 서로 맞물리는지 검사**하는 겁니다.

> 여유가 있으면 여기서 **다른 AI에게 교차 검증**시키세요.
> ChatGPT로 쓴 PRD를 Claude에게 주고 "이대로 만들 수 있나? 못 만들겠는 부분은?" 하고 물어보면
> 같은 모델이 못 보는 구멍이 나옵니다.

### 2.3 좋은 PRD 문장 vs 나쁜 PRD 문장

| ❌ | ✅ |
|---|---|
| 엑셀을 읽어서 분석한다 | `01_상품정보.xlsx`의 `상품정보` 시트를 읽는다. 23행이어야 한다 |
| 상품명을 매칭한다 | 공백·대괄호·`특가` 등을 제거해 정규화 후 정확일치. 실패 시 미매핑으로 **보존** |
| 수수료를 계산한다 | 파일에 수수료 컬럼이 있으면 그 값, 없으면 순매출 × 채널 요율 |
| 보기 좋은 대시보드 | 대시보드는 3개 질문에 답한다: ①이번달 얼마 남았나 ②어느 채널이 문제인가 ③적자 딜은 |
| 에러를 잘 처리한다 | 필수 컬럼이 없으면 **예외를 던지고 적재를 중단**한다. 빈 값으로 채우지 않는다 |

기준은 하나입니다. **"이 문장대로 만들었는지 아닌지, 제3자가 확인할 수 있는가?"**

### 2.4 흔한 실패

- **PRD를 짧게 쓴다** → 짧은 만큼 AI가 지어냅니다. 이 프로젝트 PRD는 A4 8장 정도입니다.
- **화면 얘기부터 쓴다** → 화면은 7절입니다. 계산이 먼저입니다.
- **검수 기준을 비워 둔다** → 가장 치명적. 완성 판정이 영원히 안 됩니다.
- **왕복 없이 한 방에 받는다** → 라운드 3(심문)에서 나오는 질문들이 PRD의 절반입니다.

### ✅ 2단계 완료 조건

- [ ] `docs/PRD.md` 로 저장했다
- [ ] 4절에 컬럼마다 타입·필수여부·예시가 있다
- [ ] 5절에 **손검산 예시 1건**이 있다
- [ ] 9절에 **숫자 표**가 있다
- [ ] 라운드 5에서 "추측 없이 구현 가능"이라는 답을 받았다

## 3단계 — `mock/` 폴더에 HTML 목업

### 왜 코드보다 화면이 먼저인가

수정 비용이 **10배씩** 차이 납니다.

```
목업에서 고치기     : 5분   (HTML 몇 줄)
개발 중에 고치기     : 반나절 (DB·API·화면 전부)
다 만들고 고치기     : 며칠   (+ 이미 만든 걸 버리는 손해)
```

그리고 더 중요한 이유 — **화면을 보면 PRD의 구멍이 보입니다.**
"이 표에 마진율은 있는데 이게 좋은 건지 나쁜 건지 알 수가 없네" 같은 건 그림으로만 발견됩니다.

### 3.1 목업 요청 프롬프트

```
[docs/PRD.md 전체를 붙여넣기]

위 PRD의 7절(화면)을 HTML 목업으로 만들어 줘. 조건:

- `mock/` 폴더에 화면마다 파일 하나씩. 파일명은 `01-대시보드.html` 처럼 번호를 붙여.
- **정적 HTML 한 파일**로 완결. 백엔드·DB·빌드도구 금지. 더블클릭하면 열려야 해.
- 데이터는 **PRD 9절 검수 기준의 숫자를 하드코딩**해. 진짜처럼 보이는 가짜 데이터로.
- CSS는 파일 안에 <style>로. 외부 라이브러리 금지.
- `mock/index.html` 을 만들어서 화면 목록과 데이터 흐름을 보여줘.
- **각 화면 상단에 "이 화면이 답하는 질문"을 한 문장 적어.**
- 기능은 넣지 마. 클릭해도 아무 일 안 일어나도 돼. 지금은 배치와 정보만 본다.
```

마지막 조건이 중요합니다. 목업에 기능을 넣기 시작하면 그건 목업이 아니라 개발입니다.

### 3.2 만들 화면 6장

| | 화면 | 답하는 질문 |
|:-:|---|---|
| ① | 수익률 대시보드 | 이번 달 얼마 팔아 얼마 남았나 |
| ② | 제품·딜별 수익률 | 어디서 돈이 새는가 |
| ③ | 제품 DB | 원가와 구성수량이 맞나 |
| ④ | 채널 관리 | 수수료율과 그 근거는 |
| ⑤ | 상품명 매핑 | 연결 안 된 건 무엇인가 |
| ⑥ | 매출 업로드 | 엑셀 3장을 어디에 넣나 |

### 3.3 목업 리뷰 체크리스트

브라우저로 열어 놓고 하나씩 봅니다.

- [ ] 각 화면 상단의 "답하는 질문"에 **그 화면만 보고 답할 수 있나?**
- [ ] 대시보드에서 **적자 딜이 눈에 띄나?** (숫자만 나열되면 실패)
- [ ] 마진율 옆에 **비교 기준**이 있나? (7.67%가 좋은 건지 나쁜 건지)
- [ ] **미매핑이 화면에 보이나?** 숨어 있으면 매출이 증발합니다
- [ ] `추정` 요율과 실측 요율이 **구분되나?**
- [ ] 클릭할 곳이 어디인지 알겠나?

마음에 안 들면 **말로 고칩니다.** "① 화면에서 적자 딜을 맨 위로 빼고 빨간 배지 달아 줘."
목업 단계에서는 열 번 고쳐도 몇 분입니다. 마음껏 고치세요.

### 3.4 ★ PRD로 역류시키기

목업에서 발견한 것을 **반드시 PRD 7절에 반영**하고 가세요.

```
[수정된 목업 설명 또는 파일 붙여넣기]

목업을 보면서 이런 걸 바꿨어: (변경 내용)
PRD 7절(화면)을 이 목업 기준으로 다시 써 줘. 화면마다:
- 답하는 질문 1문장
- 표시 항목 목록
- 정렬 기준 / 강조 규칙 (예: 마진율 0% 미만은 빨간 배지)
```

이걸 안 하면 4단계에서 AI가 PRD를 보고 **목업과 다른 화면을 만듭니다.**
PRD가 항상 최종 진실이어야 합니다.

### ✅ 3단계 완료 조건

- [ ] `mock/index.html` 을 브라우저에서 열면 6장이 다 보인다
- [ ] 화면을 보며 "이거 아닌데"가 더 이상 안 나온다
- [ ] 목업에서 바꾼 내용이 PRD 7절에 반영됐다

## 4단계 — 개발 + 서버 실행

### 4.1 대원칙 — 한 번에 하나, 검증 없이 다음 없음

```
❌ "PRD 보고 전체 시스템 만들어 줘"
   → 2,000줄이 한 번에 나오고, 숫자가 틀렸을 때 어디가 틀렸는지 영원히 못 찾음

✅ "1단계만 해. 상품정보 엑셀을 읽어서 행 수를 출력해. 23이 나와야 해."
   → 틀리면 5줄 안에서 찾음
```

### 4.2 착수 프롬프트

```
[docs/PRD.md 전체 붙여넣기]

이 PRD대로 만들 거야. 지금은 코드 쓰지 말고, **구현 순서만** 정해 줘.
조건:
- 단계마다 [무엇을 만드나 / 어떻게 확인하나]를 적어.
- 확인 방법은 반드시 **실행해서 눈으로 볼 수 있는 것**이어야 해.
  ("테스트 통과" 같은 말고 "이 명령을 치면 23이 출력된다" 처럼)
- 화면은 마지막에. 계산이 먼저.
```

순서를 받으면 **그 순서대로 한 단계씩** 시킵니다.

### 4.3 권장 순서와 검증 방법

| | 만드는 것 | 검증 |
|:-:|---|---|
| 1 | 파일 읽기 | 상품 23행 · 채널 14행 · 매출 3,714행이 출력된다 |
| 2 | 컬럼명 통일 | 5개 시트가 같은 컬럼 구조로 합쳐진다 |
| 3 | 상품명 매핑 | 매칭 3,707 / 미매핑 7건 · 214,300원 |
| 4 | **한 줄 계산** | PRD 5절 손검산 예시와 **완전히 일치** |
| 5 | 전체 합계 | 검수 표 8개 숫자가 전부 일치 |
| 6 | 집계 (채널별·제품별·주별) | 적자 딜 3건이 나온다 |
| 7 | 화면 | 목업과 같은 배치, 진짜 데이터 |
| 8 | 결과 엑셀 | 6시트, 미매핑 시트 포함 |

**4번이 관문입니다.** 한 줄이 맞으면 전체는 대개 맞습니다. 한 줄이 틀리면 전체가 틀립니다.
4번에서 시간을 아끼지 마세요.

### 4.4 서버 켜기

```bash
.venv/bin/python -m uvicorn app.web:app --reload --port 8010
```

→ http://127.0.0.1:8010

서버가 안 뜨면 **에러 메시지 전체를 그대로 복사해서** AI에게 주세요. 요약하지 마세요.

띄운 뒤 확인할 것:

- [ ] 대시보드 숫자가 검수 표와 같다
- [ ] 미매핑 7건이 화면에 보인다
- [ ] 적자 딜 3건이 표시된다
- [ ] `추정` 배지가 해당 채널에만 붙는다
- [ ] 업로드 → 같은 파일 재업로드 시 매출이 두 배가 되지 않는다
- [ ] 결과 엑셀이 받아지고 6시트가 다 있다

### 4.5 막혔을 때

**에러가 났다**

```
이 에러가 났어. 원인이 뭐고 어떻게 고쳐야 해?
[에러 전체를 그대로 붙여넣기 — 마지막 줄만 말고 전부]
```

**숫자가 안 맞는다** — 범위를 좁혀 갑니다.

```
총매출이 77,667,300이어야 하는데 79,120,000이 나와. 차이가 1,452,700이야.
전체를 고치기 전에, 채널별 총매출을 먼저 출력해 줘. 어느 채널에서 벌어지는지 보자.
```

그다음 그 채널의 시트 하나, 그다음 행 하나로 좁힙니다. **이분 탐색이 가장 빠릅니다.**

**숫자 안 맞을 때 의심할 6가지**

1. 취소 건에서 원가를 안 지웠다
2. 구성수량을 안 곱했다
3. 수수료를 전 채널 동일 요율로 계산했다
4. 미매핑을 버렸다 (합계가 작아짐)
5. 같은 파일을 두 번 적재했다 (합계가 두 배)
6. 매입가를 최신 값으로 썼다 (판매일 기준이어야 함)

### 4.6 절대 하면 안 되는 것

| 하지 마세요 | 왜 |
|---|---|
| 숫자를 맞추려고 값을 하드코딩 | 다음 달 데이터에서 즉시 무너짐 |
| 미매핑을 조용히 제외 | 매출이 증발함. 화면에 노출해야 함 |
| 이해 못 한 코드를 그냥 넘김 | "이 부분 한 줄씩 설명해 줘"라고 물으세요 |
| 검증 없이 다음 단계 | 틀린 위치를 못 찾게 됨 |
| AI가 "잘 동작합니다"라고 하면 믿기 | **직접 실행해서 숫자를 보세요** |

### ✅ 4단계 완료 조건

- [ ] 검수 표 8개 숫자가 전부 일치
- [ ] 서버가 뜨고 화면 6개가 다 열린다
- [ ] 빈 DB에 엑셀 3장만 넣어도 같은 숫자가 나온다

## 5단계 — git 배포

### 왜 git인가

두 가지 때문입니다.

1. **되돌리기.** AI가 잘 돌던 코드를 망가뜨리는 일은 반드시 생깁니다. 커밋이 있으면 1초 만에 되돌립니다.
2. **넘겨주기.** "제 PC에서는 되는데요"를 없앱니다.

### 5.1 ⚠ 먼저 — `.gitignore`

**순서를 지키세요. 커밋 전에 만듭니다.** 한 번 올라간 파일은 지워도 이력에 남습니다.

```gitignore
# 가상환경
.venv/
__pycache__/
*.pyc

# 데이터베이스 (매번 다시 만들 수 있음)
data/*.db

# ★ 실제 매출 데이터 — 절대 올리지 마세요
docs/inbox/**/*.xlsx
*_실매출*.xlsx

# OS
.DS_Store
```

실제 매출 엑셀에는 **주문번호·수취인·매입가**가 들어 있습니다.
공개 저장소에 올라가면 회사 원가 구조가 그대로 노출됩니다. 목업 데이터만 올리세요.

### 5.2 첫 커밋

```bash
git init && git add . && git status
```

`git status` 목록을 **눈으로 확인**하세요. 올리면 안 될 게 있으면 여기서 걸립니다.

```bash
git commit -m "feat: 매출 관리 시스템 초기 구현"
```

### 5.3 커밋 단위 — 4단계의 각 단계마다 하나씩

```
feat: 엑셀 3종 적재
feat: 상품명 매핑 (정확일치 + 미매핑 보존)
feat: 딜 단위 손익 계산
feat: 대시보드 · 제품별 · 채널별 화면
feat: 결과 엑셀 6시트 내보내기
docs: README 및 검수 기준
```

**되돌릴 수 있는 지점**을 만드는 게 목적입니다. 하루치를 한 커밋에 몰지 마세요.

되돌릴 때:

```bash
git log --oneline && git checkout <커밋해시> -- <파일경로>
```

### 5.5 GitHub에 올리기

```bash

```

`gh`가 없으면 GitHub 웹에서 저장소를 만들고:


# 마무리 — 이 흐름이 왜 통하나

각 단계가 **다음 단계의 입력이자, 틀렸을 때 돌아갈 곳**이기 때문입니다.

```
1. 파일    → 현실을 고정한다
2. PRD     → 현실을 문장으로 고정한다      ← 목업에서 발견한 것이 여기로 역류
3. 목업    → 문장을 그림으로 검증한다
4. 개발    → 그림을 숫자로 검증한다
5. git     → 숫자를 남에게 넘긴다
```

실패는 거의 항상 **2단계를 얇게 쓰고 4단계로 뛴 것**입니다.
그렇게 만든 코드는 잘 돌아가는 것처럼 보이고, 숫자만 조용히 틀립니다.
그리고 숫자가 틀렸다는 걸 **월말 결산에서 알게 됩니다.**

> **세 줄 요약**
> 1. 확인할 수 있게 시켜라 — "잘 만들어줘"가 아니라 "23이 나와야 해"
> 2. 정답부터 만들어라 — 검수 기준 없이 시작하면 완성을 판정할 수 없다
> 3. 한 번에 하나씩 — 검증 안 된 단계 위에 다음 단계를 쌓지 마라
