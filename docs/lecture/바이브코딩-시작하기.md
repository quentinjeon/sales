# 바이브코딩으로 매출 관리 시스템 만들기

> **프로그래밍을 한 번도 안 해본 분을 위한 안내입니다.**
> 코드를 외울 필요도, 문법을 배울 필요도 없습니다.
> 대신 **무엇을 만들지 정확하게 말하는 법**을 배웁니다. 그게 전부입니다.

---

## 0. 오늘 만들 것

엑셀 3장을 넣으면 이런 화면이 나오는 웹 도구입니다.

```
📦 상품정보.xlsx  ─┐
🛒 채널정보.xlsx  ─┼─→  [ 내가 만들 프로그램 ]  ─→  📊 대시보드
🧾 매출.xlsx      ─┘
```

완성되면 이런 걸 알 수 있습니다.

> "이번 달 매출 7,766만원, **손에 남은 건 595만원(7.67%)**.
> 그리고 **얼큰라면 멀티팩은 팔수록 손해**라 155건 팔아서 15만원을 잃었다."

먼저 결과부터 보고 시작합시다. 브라우저로 열어보세요.

```
mock/index.html
```

**목표를 눈으로 본 다음에 만드는 것**과 그냥 만드는 것은 완전히 다릅니다.

---

## 1. 바이브코딩이 뭔가

AI에게 **말로 시켜서** 프로그램을 만드는 방식입니다.

```
❌ 예전:  문법을 배운다 → 코드를 친다 → 에러를 고친다 → (몇 달)
✅ 지금:  뭘 만들지 설명한다 → AI가 만든다 → 확인한다 → 고쳐달라고 한다
```

### 그래서 실력이 뭐로 갈리나

코딩 실력이 아니라 **설명하는 실력**입니다. 이 둘을 비교해 보세요.

| | |
|---|---|
| ❌ | "엑셀 읽어서 매출 분석해줘" |
| ✅ | "`01_상품정보.xlsx`의 `상품정보` 시트를 읽어서 행 수를 출력해줘. 23이 나와야 해." |

두 번째는 **틀렸는지 바로 알 수 있습니다.** 그게 핵심입니다.

> **바이브코딩의 제1원칙**
> AI는 모르면 지어냅니다. 모호하게 말하면 그럴듯한 거짓말을 받습니다.
> **확인할 수 있게 시켜야** 합니다.

---

## 2. 준비물

| 필요한 것 | 설명 |
|---|---|
| AI 코딩 도구 | Claude Code, Cursor, 또는 Copilot 중 아무거나 |
| 실습 파일 3장 | `docs/lecture/실습데이터/` 폴더 |
| 명세서 | [docs/PRD.md](../PRD.md) — **이게 오늘의 무기입니다** |
| 정답지 | `docs/lecture/결과예시/` — 내 결과가 맞는지 대조용 |

설치나 환경 설정에서 막히면 **그것부터 AI에게 물어보세요.** 그것도 바이브코딩입니다.

---

## 3. 시작하기 전에 딱 하나만

### PRD를 먼저 통째로 줍니다

가장 흔한 실패는 이렇게 시작하는 겁니다.

```
❌ "매출 관리 시스템 만들어줘"
```

AI는 뭘 만들지 모르니 **자기가 상상한 걸** 만듭니다. 그리고 그건 내가 원한 게 아닙니다.

대신 첫 메시지를 이렇게 시작하세요.

```
✅ 아래는 내가 만들 시스템의 명세서(PRD)야. 전부 읽고, 질문이 있으면 먼저 물어봐.
   아직 코드는 짜지 마.

   [docs/PRD.md 내용 전체 붙여넣기]
```

**"아직 코드는 짜지 마"** 가 중요합니다.
AI가 이해했는지 먼저 확인하고, 그 다음에 시킵니다.

---

## 4. 단계별로 시키기 ★ 이게 전부입니다

한 번에 다 시키면 실패합니다. **8단계로 쪼개서, 매 단계 숫자를 확인**합니다.

### 1단계 — 파일 읽기

```
실습데이터 폴더의 엑셀 3개를 읽어서 각각 몇 행인지만 출력하는 코드를 짜줘.
아직 계산은 하지 마.
```

**확인**: `23` / `14` / `3714` 가 나와야 합니다.

> 여기서 안 맞으면 파일 경로나 시트 이름이 틀린 겁니다. **절대 다음으로 넘어가지 마세요.**

---

### 2단계 — 컬럼 이름 통일

```
매출 파일은 채널마다 시트가 있고 컬럼 이름이 전부 달라.
PRD 4.3의 표대로 공통 이름(주문일/상품명/옵션명/수량/판매금액/수수료)으로 바꿔서
5개 시트를 하나의 표로 합쳐줘.

합친 결과가 3,714행인지, 그리고 각 채널별 행 수를 출력해줘.
```

**확인**: 합계 3,714행. 한빛홈쇼핑이 가장 많아야 합니다.

---

### 3단계 — 상품명 연결

```
매출 데이터의 상품명을 상품정보의 제품명과 연결해줘.
정확히 일치하지 않는 건 '미매핑'으로 표시하고, 절대 버리지 마.
미매핑이 몇 건이고 금액이 얼마인지 출력해줘.
```

**확인**: **7건 / 214,300원**

> 미매핑이 0건이면 뭔가 잘못 매칭한 겁니다. 일부러 안 맞는 데이터를 넣어놨습니다.

---

### 4단계 — 한 줄 계산

```
PRD 5절의 계산 규칙대로 주문 한 줄의 손익을 계산하는 함수를 만들어줘.
금액은 전부 정수(원 단위)로. 소수점 쓰지 마.

만들고 나서 PRD 5절의 예시 한 줄을 넣어 결과를 출력해줘.
```

**확인**: 기여이익 **1,294원**, 마진율 **5.20%**

> 여기가 이 시스템의 심장입니다. 여기서 틀리면 나머지가 전부 틀립니다.

---

### 5단계 — 전체 합계

```
이제 3,714행 전부에 계산을 적용하고 전체 합계를 출력해줘.
총매출 / 수수료 / 원가 / 물류비 / 기여이익 / 마진율 순으로.
```

**확인**:

| 항목 | 값 |
|---|---:|
| 총매출 | 77,667,300 |
| 수수료 | 8,711,768 |
| 원가 | 52,072,450 |
| 물류비 | 10,928,600 |
| **기여이익** | **5,954,482** |
| 마진율 | 7.67% |

> 하나라도 다르면 **왜 다른지 찾을 때까지** 다음으로 가지 마세요.
> 아래 6절에 흔한 원인이 정리돼 있습니다.

---

### 6단계 — 집계

```
제품별, 채널별로 집계해서 표로 출력해줘.
채널별은 매출 순, 제품별은 기여이익 순으로 정렬해줘.
```

**확인**: 채널별 표가 PRD 9절과 같아야 합니다. 한빛홈쇼핑 매출 26,728,500 / 이익 2,483,980.

---

### 7단계 — 화면

```
웹 대시보드를 한 페이지로 만들어줘. FastAPI + Jinja2 템플릿으로.
화면 구성은 mock/04-대시보드.html 을 참고해줘. 위에서부터:
1) KPI 4장 (총매출/기여이익/마진율/미매핑)
2) 적자 딜 경고 (빨간 박스)
3) 채널별 손익 표
4) 제품별 기여이익 표
5) 주별 추이 막대
```

**확인**: 적자 딜이 **정확히 3건** 보여야 합니다.

---

### 8단계 — 엑셀 내보내기

```
결과를 엑셀로 내보내는 기능을 추가해줘. 시트 6장은 PRD 8절 표대로.
```

**확인**: `결과예시/결과_2026-07.xlsx` 와 시트 구성이 같아야 합니다.

## 5. 막혔을 때

### 에러가 났다

**에러 메시지를 통째로 복사해서 붙여넣으세요.** 요약하지 마세요.

```
✅ 이런 에러가 났어. 원인이 뭐고 어떻게 고치면 돼?

   Traceback (most recent call last):
     File "main.py", line 42, in <module>
   KeyError: '상품명'
```

AI는 에러 메시지에서 대부분의 정보를 얻습니다. "에러 났어"라고만 하면 추측만 합니다.

### 숫자가 안 맞는다

```
✅ 기여이익이 6,120,000원 나왔는데 정답은 5,954,482원이야.
   165,518원 차이나. 어디서 틀렸는지 단계별로 확인해줘.
```

**차이 금액을 알려주는 게 핵심입니다.** 그 숫자가 원인을 좁혀 줍니다.

### 코드가 뭔 소린지 모르겠다

부끄러워할 일이 아닙니다. 그냥 물어보세요.

```
✅ 방금 만든 코드에서 이 부분이 무슨 일을 하는지 한 줄씩 한국어로 설명해줘.
   나는 프로그래밍을 처음 해.
```

### AI가 자꾸 딴 걸 만든다

대화가 길어지면 AI가 앞을 잊습니다. 다시 붙잡아 주세요.

```
✅ 잠깐. 지금 우리가 하는 건 PRD 5절의 계산 규칙을 구현하는 거야.
   다른 기능은 추가하지 말고 그것만 해줘.
```

---

## 6. 숫자가 안 맞을 때 — 원인 6가지

거의 다 여기에 있습니다. 위에서부터 확인하세요.

| 증상 | 원인 | 확인 방법 |
|---|---|---|
| 이익이 너무 큼 | **구성수량을 안 곱했다** (24·30·1000개입!) | 원가 52,072,450원 맞나 |
| 몇 원씩 안 맞음 | 실수(float)로 금액을 다뤘다 | 반올림을 수수료에서 한 번만 하나 |
| 매출이 정답보다 큼 | `WAITING` 채널을 넣었다 | 채널이 5개만 나오나 |
| 매출이 정답보다 작음 | 미매핑을 버렸다 | 미매핑 7건이 살아있나 |
| 채널 합 ≠ 전체 | 시트를 빠뜨렸다 | 5개 시트 다 읽었나 |
| 마진율이 이상함 | 0으로 나눴다 | 순매출 0인 줄 처리했나 |

---

## 7. 하면 안 되는 것

| 하지 마세요 | 이유 |
|---|---|
| "알아서 잘 만들어줘" | AI가 상상한 걸 받습니다. 내가 원한 게 아닙니다 |
| 한 번에 8단계 다 시키기 | 어디서 틀렸는지 못 찾습니다 |
| 숫자 확인 없이 다음 단계 | 앞이 틀리면 뒤는 전부 틀립니다 |
| 코드를 안 읽고 넘어가기 | 최소한 **어디가 뭘 하는지**는 알아야 고칠 수 있습니다 |
| 에러를 요약해서 전달 | 원인 정보가 그 안에 있는데 버리는 겁니다 |

## 8. 끝나고 나면

여기까지 하면 **자기 회사 데이터로 바꿔볼 수 있습니다.**

1. `01_상품정보.xlsx` 를 자기 회사 제품으로 교체
2. `02_채널정보.xlsx` 에 실제 수수료율 입력
   → 정산서에서 `수수료 합계 ÷ 매출 합계` 로 역산
3. 지난달 매출 파일 넣고 돌리기

그리고 **적자 딜이 나오는지 보세요.**
거의 모든 회사에 하나 이상 있습니다. 그걸 찾는 게 이 도구의 존재 이유입니다.

### 더 해볼 것

| | 프롬프트 예시 |
|---|---|
| 손익분기가 | "각 제품이 채널별로 최소 얼마에 팔아야 본전인지 계산해줘. `(원가+물류비) ÷ (1−수수료율)`" |
| 채널 재배치 | "적자 딜을 수수료가 가장 낮은 채널로 옮기면 이익이 얼마나 늘어나는지 계산해줘" |
| 미매핑 자동 제안 | "미매핑 상품명에 대해 이름이 비슷한 제품 3개를 후보로 띄워줘" |
| 월별 비교 | "지난달과 이번달을 나란히 비교하는 화면을 추가해줘" |

---

## 요약 — 딱 세 줄

1. **PRD를 먼저 통째로 준다.** 그리고 "아직 코드는 짜지 마"라고 한다.
2. **8단계로 쪼개고, 매 단계마다 숫자를 확인**한다. 안 맞으면 다음으로 안 간다.
3. 막히면 **에러 전문과 차이 금액**을 그대로 붙여넣는다.

이 세 개만 지키면 오늘 안에 만들 수 있습니다.

> 손익 구조만 실무와 같게 설계했습니다. 실존 기업과 무관합니다.
