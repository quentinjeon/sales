# PRD — 월별 매출·수익률 관리 시스템

> **이 문서의 용도**
> 바이브코딩 수업에서 **AI에게 그대로 붙여넣는 명세서**입니다.
> 사람이 읽는 기획서가 아니라, AI가 코드를 만들 수 있을 만큼 구체적으로 쓴 지시서입니다.
> 모호한 문장이 하나도 없어야 합니다 — 모호하면 AI가 지어냅니다.

---

## 1. 한 줄 요약

**엑셀 3장을 넣으면, 그 달의 「제품별 매출」과 「채널별 매출·이익률」을 보여주는 웹 대시보드.**

```
01_상품정보.xlsx  ─┐
02_채널정보.xlsx  ─┼─→  [ 계산 ]  ─→  결과 엑셀 + 웹 대시보드
03_매출_2026-07.xlsx ─┘
```

---

## 2. 왜 만드는가

온라인몰을 파는 회사는 **총매출은 알지만 이익은 모릅니다.**

- 채널마다 수수료가 다릅니다 (6.8% ~ 24.0%). 그런데 다들 "대충 13%"로 가정합니다.
- 채널마다 상품명이 다릅니다. 그래서 제품 단위로 합산이 안 됩니다.
- 원가·물류비가 빠진 숫자를 보고 "잘 팔린다"고 판단합니다.

**결과**: 팔수록 손해인 제품을 모르고 계속 팝니다.
이 시스템은 그걸 숫자로 드러냅니다.

---

## 3. 범위

### 만든다 (P0)

- 엑셀 3장 읽기 (채널마다 컬럼명이 다른 것 포함)
- 상품명 → 제품 매칭
- 주문 한 줄마다 손익 계산
- 제품별 / 채널별 / 채널×제품 집계
- 웹 대시보드 1화면 + 결과 엑셀 내보내기

### 안 만든다 (이번 수업 범위 밖)

- 로그인·권한 — 혼자 쓰는 내부 도구입니다
- 반품·쿠폰·부가세 정밀 처리 — 2차 과제
- 실시간 API 연동 — 엑셀 업로드로 충분합니다
- 여러 달 비교 — 한 달만 제대로 보면 됩니다

> **범위를 줄이는 게 이 PRD의 핵심입니다.**
> 바이브코딩에서 가장 흔한 실패는 "다 되게 해줘"라고 시켜서 아무것도 안 되는 것입니다.

| 컬럼 | 타입 | 예시 | 설명 |
|---|---|---|---|
| 제품코드 | 문자 | `RICE24` | 고유값 |
| 제품명 | 문자 | `온담 무균 즉석밥 210g 24개입` | |
| 규격 | 문자 | `210g x 24개` | 표시용, 계산에 안 씀 |

## 5. 계산 규칙 ★ 가장 중요

주문 **한 줄마다** 아래 순서로 계산합니다.

```
① 순매출   = 판매금액

② 수수료   = 파일에 수수료 컬럼이 있으면  → 그 값을 쓴다
             없으면                      → 순매출 × 채널 수수료율, 반올림

③ 원가     = (매입가 × 구성수량) × 판매수량

④ 물류비   = 채널 물류비 × 판매수량      (채널부담이면 0)

⑤ 기여이익 = 순매출 − 수수료 − 원가 − 물류비

⑥ 마진율   = 기여이익 ÷ 순매출          (순매출이 0이면 공란)
```

### 지켜야 할 것

| 규칙 | 이유 |
|---|---|
| 금액은 **원 단위 정수**. 소수점 금지 | 0.1원이 3,700줄 쌓이면 합계가 안 맞습니다 |
| 수수료는 **실적값 우선** | 채널이 준 실제 숫자가 요율 추정보다 정확합니다 |
| 반올림은 **수수료 계산에서 한 번만** | 여러 번 반올림하면 합계가 어긋납니다 |
| `ACTIVE`가 아닌 채널은 제외 | 아직 안 파는 채널입니다 |
| **같은 파일·같은 주문번호는 두 번 넣지 않는다** | 재업로드 한 번에 매출이 두 배가 됩니다 |

### 계산 예시 — 이 한 줄을 손으로 검산해 보세요

```
매출 파일 한 줄:  온담 무균 즉석밥 210g 24개입 | 1건 | 24,900원 | 한빛홈쇼핑

① 순매출   24,900
② 수수료   24,900 × 9.5% = 2,365.5 → 2,366      (수수료 컬럼 있으면 그 값)
③ 원가     760 × 24 × 1 = 18,240
④ 물류비   3,000 × 1 = 3,000
⑤ 기여이익 24,900 − 2,366 − 18,240 − 3,000 = 1,294
⑥ 마진율   1,294 ÷ 24,900 = 5.20%
```

같은 줄을 몰이십일(13.0%)에서 팔면 수수료가 3,237원이 되어 이익은 **423원(1.70%)**.
**매출은 같은데 이익이 67% 줄어듭니다.** 이 시스템이 존재하는 이유입니다.

## 6. 상품명 매칭

매출 파일의 상품명은 상품정보의 제품명과 **글자가 정확히 같지 않을 수 있습니다.**

오픈마켓 상품명은 검색 키워드를 잔뜩 붙여 등록합니다.

```
상품정보:  온담 무균 즉석밥 210g 24개입
매출파일:  [7월 특가] 온담 무균 즉석밥 210g 24개입 햇반 대체 즉석밥
```

### 요구사항

1. 정확히 일치하면 바로 연결
2. 일치하지 않으면 **미매핑**으로 남기고 화면에 반드시 보여준다
3. **미매핑을 조용히 버리지 않는다** — 버리면 매출이 증발합니다

> 실습 데이터에는 **일부러 안 맞는 7건(214,300원)** 이 들어 있습니다.
> 이게 화면에 안 보이면 틀린 구현입니다.

## 10. 기술 스택

정답은 없습니다. 아래는 **AI가 가장 안정적으로 만들어 주는 조합**입니다.

| 영역 | 추천 | 이유 |
|---|---|---|
| 언어 | Python | 엑셀 처리 라이브러리가 가장 풍부 |
| 엑셀 읽기 | pandas + openpyxl | AI가 예제를 가장 많이 학습한 조합 |
| 웹 | FastAPI + Jinja2 템플릿 | 파일 몇 개로 끝남. React는 이번 범위에 과함 |
| 저장 | SQLite 또는 메모리 | 혼자 쓰는 도구에 DB 서버는 과함 |

**단순한 걸 고르세요.** 바이브코딩에서 스택이 복잡하면 AI가 만든 코드를 사람이 못 고칩니다.

## 12. 자주 나오는 실수

| 증상 | 원인 |
|---|---|
| 매출이 정확히 2배 | 같은 파일을 두 번 적재했다 (중복 검사 없음) |
| 이익이 비정상적으로 큼 | 구성수량을 안 곱했다 (원가가 절반) |
| 합계가 몇 원씩 안 맞음 | 반올림을 여러 번 했거나 실수(float)로 금액을 다뤘다 |
| 매출이 정답보다 큼 | `WAITING` 채널을 계산에 넣었다 |
| 매출이 정답보다 작음 | 미매핑을 조용히 버렸다 |
| 마진율이 이상함 | 순매출이 0인 줄에서 나눗셈을 했다 |
| 채널별 합이 전체와 다름 | 시트 하나를 빠뜨렸다 |
